Right-clicking a sidebar project or environment pill had no menu, so the only way to keep a
stale device or project out of the view was to re-pick the scope. The pills now answer a
right-click: a project offers "Remove from view", an environment offers "Exclude", and both
fold into the +N control's "Hidden" group, where one click brings them back. Exclusions persist
in localStorage. The device menu never offers "This computer".

How: `resolveEnvironmentFilter` (client-runtime) now takes the hidden environment ids and
returns them as `hiddenPills`; the sidebar adds the two context-menu handlers, two
localStorage stores, and a +N overflow menu. The project picker keeps a removed project
searchable and marks it "Hidden" until it is brought back.

Scope: desktop/web only. Not included: environment "Stop" (needs the per-environment stop path
wired to the sidebar), mobile long-press, and #1240 (pills as global scope). Tracked for follow-up.

Evidence: client-runtime and web logic tests pass; the environment-filter browser test renders
the row at real widths and drives the +N menu; additive guard and typecheck are green. Pixel
before/after screenshots pending — this host runs one browser at a time.

Rerender: n/a, the change threads props into the existing measured pill row and swaps the
overflow for a menu; no new per-render state a list row could pick up.
