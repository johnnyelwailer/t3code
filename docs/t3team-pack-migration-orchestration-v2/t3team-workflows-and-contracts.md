# 3.9 Workflows, recipes and SDK, 3.10 removed settings and env vars, 3.11 RPC and contract moves

Part of the [pack migration guide](../t3team-pack-migration-orchestration-v2.md).

## 3.9 Workflows, recipes and the SDK

| Area                                                               | Before                                                                                                                                                                                                        | After                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SDK builtin                                                        | `tools.t3team.thread.rename`, `renameThreadTool`, `RenameThreadToolArgs` / `Result`, subpath `@t3team/sdk/tools/t3team`, `builtinTools` / `BuiltinToolsTree`, required `T3TeamToolHandlerClient.renameThread` | all _removed_ (no host ever wired it); `tools` is typed `RegisteredWorkflowToolsTree`; `T3TeamToolHandlerClient` has no required member; agents rename with `t3_thread_update` (`packages/t3team-sdk/src/t3team-sdk.toolsIndex.ts`, `t3team-sdk.types.ts`)                                                                             |
| `askAgent` / `agent` answer                                        | first final assistant message after the prompt                                                                                                                                                                | the RUN the prompt started reaches a terminal; answer = that run's last substantive assistant message (never an opening preamble); failed or interrupted runs are re-driven as fresh queued prompts (budget 3, journaled); a completed run with no assistant text fails the workflow run (`apps/server/src/t3team-workflowTurnRun.ts`) |
| Step prompt held in a paused queue                                 | waited forever                                                                                                                                                                                                | the workflow cancels that one queued run (`queued-run.cancel`, command id `t3team-wf-held:<runId>`) and re-drives the step; other held messages stay held                                                                                                                                                                              |
| Step prompts                                                       | `t3teamExt` author on a V1 message                                                                                                                                                                            | `message.dispatch` `queue_after_active`, `createdBy: "system"`, author `{kind: "workflow", workflowRunId, stepId, label}` in the message context; tell machine input from a person by `readT3TeamMessageExtContext(message.context)?.author`                                                                                           |
| `notifyAgent`                                                      | hidden agent-visible message, no turn                                                                                                                                                                         | a queued prompt that STARTS a turn; nothing waits for the reply; use `askAgent` when the reply matters                                                                                                                                                                                                                                 |
| `notifyUser`, completion/failure notice, shape preview, run report | messages in the agent transcript                                                                                                                                                                              | run-less `system` messages (`system_notice`), visible to the person, not in the agent transcript; agents learn a run's outcome from the run status tools or `askAgent`                                                                                                                                                                 |
| `askUser` answer                                                   | V1 user message (`t3teamExt.workflowReply`)                                                                                                                                                                   | the next message a PERSON posts (`role: "user"`, `createdBy: "user"`); structured replies via `withT3TeamMessageExtContext({ workflowReply: { value, correlationId } })`; widget replies never answer                                                                                                                                  |
| `POST /api/t3team/thread/workflow/resolve-input`                   | V1 user message                                                                                                                                                                                               | run-less user message (`creationSource: "web"`, idempotent on `messageId`), reply in the context ext `workflowReply`, no agent turn                                                                                                                                                                                                    |
| Rich rows                                                          | `t3teamExt.attachments`, `t3team.recipe.workflow.step` activities                                                                                                                                             | thread artifacts (3.6); run status and wake deadline as facts `workflowRunStatus` / `sleepingUntil`                                                                                                                                                                                                                                    |
| Children (`spawnThread`, `agent()`, repair helpers)                | V1 `thread.create` plus relation metadata                                                                                                                                                                     | V2 threads with `subagent` lineage under the launch thread; one-shot and repair helpers carry `retention: "ephemeral"` (`apps/server/src/t3team-workflowChildPlacement.ts`)                                                                                                                                                            |
| Stop / abort                                                       | `thread.turn.interrupt` per run thread                                                                                                                                                                        | interrupts the ACTIVE run on each run thread; an already queued workflow prompt is not cancelled                                                                                                                                                                                                                                       |
| Clock wakes                                                        | in-process timer, 1 s floor, `WorkflowSchedulerClock`, `stop`                                                                                                                                                 | upstream `Scheduler` sweep (5 s tick); `makeWorkflowScheduler({listSleeping, resume, now?})` returns `{rearm, runDue}`; sub-5 s precision unsupported (`apps/server/src/t3team-workflowScheduler*.ts`)                                                                                                                                 |
| Signal reconciler                                                  | `stop()`, `sweepMs`, `startTimer`, `startSignalSweep`                                                                                                                                                         | removed; periodic sweep is a `Scheduler` source; `reconcile()` / `sweep()` resolve after boot rehydration; `WorkflowSignalRehydrateGateShape` gains `completed: Promise<void>`; author-defined signal sources unchanged, but none may assume delivery before rehydration                                                               |
| Broker workflow tools and control route                            | enabled with run registry, repository, journal, scheduler                                                                                                                                                     | also need `T3TeamWorkflowHost` in context, else "not enabled"                                                                                                                                                                                                                                                                          |
| Recipe E2E report                                                  | `commandTypes`, `capture.commands`, `summarizeT3TeamHarnessCommands`                                                                                                                                          | `hostOperations`, `capture.operations: {op, input}[]`, `summarizeT3TeamHarnessOperations`; the launch thread runs on `WORKFLOW_STUB_MODEL_SELECTION` (`apps/server/src/t3team-recipeWorkflowHarnessReport.ts`, `t3team-recipeWorkflowE2e.ts`)                                                                                          |
| Engine host seam (host code)                                       | `dispatch(command: OrchestrationCommand)` on launch, run-control and broker deps                                                                                                                              | `host: WorkflowHostPort {createThread, startTurn, postMessage, upsertActivity, interrupt, syncRunFacts}`; service `T3TeamWorkflowHost`, adapter `toWorkflowHostPort`, test fake `makeFakeWorkflowHost()` (`apps/server/src/t3team-workflowHostPort.ts`, `t3team-workflowHost.ts`, `t3team-workflowHostFake.fixtures.ts`)               |

Pack provider requirement: end every turn with a terminal and put the answer in the turn's last
assistant message, or `askAgent` steps re-drive and eventually fail.

## 3.10 Removed settings and environment variables

| Name                                                                       | Replacement                                                            |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `T3TEAM_DEFAULT_MODEL_INSTANCE_ID`, `T3TEAM_DEFAULT_MODEL`                 | `defineModelPolicy.defaultModelSelection` (3.2)                        |
| `T3TEAM_TEXT_GENERATION_MODEL_INSTANCE_ID`, `T3TEAM_TEXT_GENERATION_MODEL` | `defineModelPolicy.textGenerationModelSelection` (3.2)                 |
| `T3TEAM_CHILD_CLEANUP_NUDGE_AT`, `T3TEAM_CHILD_CLEANUP_NUDGE_COOLDOWN_MS`  | none (completion wake plus child settle sweeper)                       |
| `T3TEAM_THREAD_LIVENESS_TTL_MS`                                            | none (shell `pendingBackgroundTasks`)                                  |
| `T3TEAM_ACTOR_MESSAGE_DELIVERY_MAX_CHARS`                                  | none (only served V1 rehydrate matching)                               |
| `T3TEAM_PROVIDER_USAGE_DEV_FORCE`                                          | none (upstream `UsageLimitRecoveryWorker`)                             |
| `T3TEAM_RAW_TOOL_INJECTION_JSON`                                           | none (module deleted; unread before the sync)                          |
| `T3CODE_STRICT_PROVIDER_LIFECYCLE_GUARD` (upstream V1)                     | none (V1 provider ingestion deleted)                                   |
| setting `ServerSettings.showLocalProviderSessions` (and its patch key)     | upstream `agentSessions.scan` / `import`; the key is ignored on decode |

Unchanged: `T3TEAM_ACTOR_MESSAGE_DEBOUNCE_MS`, `T3TEAM_ACTOR_MESSAGE_BATCH_MAX`,
`T3TEAM_CHILD_SETTLE_TTL_MS`, `T3TEAM_CHILD_SETTLE_SWEEP_INTERVAL_MS`,
`T3TEAM_CHILD_SETTLE_RETRY_BLOCK_MS`, `T3TEAM_CHILD_SETTLE_STARTUP_GRACE_MS`, `T3TEAM_PACKS_DIR`,
`T3CODE_DISTRIBUTION`.
